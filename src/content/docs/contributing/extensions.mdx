import EveFit from "@/components/docs/eve/EveFit.astro";
import EveLocText from "@/components/docs/eve/EveLocText.tsx";
import EveType from "@/components/docs/eve/EveType.tsx";
import EveTypePrice from "@/components/docs/eve/EveTypePrice.astro";

本文记录当前站点可在 MDX 中直接使用的 EVE 文档组件。它们在渲染时都只读取仓库内已生成的数据。
其中 `EveTypePrice` 会在 `build:collect` 阶段收集 `(regionId, typeId)` 引用，
再由额外的价格生成步骤拉取 EveTycoon 的市场快照，最终静态写入仓库内的生成文件。

> 如果 `src/generated/eve/data.ts` 还没有针对当前文档引用完成同步，这些组件会回退为
> `type:...`、`loc:...` 和占位图标，以保证构建本身不被阻塞。

## 导入方式

```mdx
import EveFit from "@/components/docs/eve/EveFit.astro";
import EveLocText from "@/components/docs/eve/EveLocText.tsx";
import EveType from "@/components/docs/eve/EveType.tsx";

```

## `EveType` API

| Prop     | Type               | Default  | 说明                                                           |
| -------- | ------------------ | -------- | -------------------------------------------------------------- |
| `typeId` | `number`           | Required | TQ `type_id`。                                                 |
| `size`   | `number \| string` | Required | 内联图像尺寸。推荐始终显式传入，例如 `24`、`32` 或 `"1.5em"`。 |

行为说明：

- 正文中显示类型的 `zh-CN` 名称。
- 正文前缀会显示类型图像，优先取 `graphics`，其次回退到 `icons`。
- 如果类型存在 Meta Group 图标，会在页面渲染时叠加一个小角标，而不会修改原始图片资产。
- 悬停浮层会显示名称、描述、组、类别、Meta Group 以及图像来源信息。

```mdx
可以直接写 <EveType typeId={28665} size={32} /> 或 <EveType typeId={28666} size={32} />。
```

## `EveTypePrice` API

| Prop       | Type               | Default    | 说明                                                             |
| ---------- | ------------------ | ---------- | ---------------------------------------------------------------- |
| `typeId`   | `number`           | Required   | TQ `type_id`。                                                   |
| `regionId` | `number`           | `10000002` | 市场区域 ID。默认值为 The Forge。                                |
| `size`     | `number \| string` | `16`       | 为兼容旧调用点保留；当前版本不再显示前缀图像，因此没有可见效果。 |

行为说明：

- 正文中会直接显示两行价格，分别对应卖单与买单，数值颜色分别为红色与绿色。
- 价格数据来自 `packages/eve-docs-generator/` 提供的 Python 生成器
  `pnpm generate:eve-type-price-data` 写出的静态文件
  `src/generated/eve/type-price-data.ts`，并使用 EveTycoon 返回的
  `sellAvgFivePercent` 与 `buyAvgFivePercent`。
- `build:collect` 会把组件引用写入 `src/generated/eve-type-prices.json`，
  该文件专门用于跟踪价格组件的 `(regionId, typeId)` 清单，避免和
  `src/generated/extension-ids.json` 混在一起。
- 行内标签文本和无数据文案通过 Starlight UI 翻译系统渲染，键位定义在
  `src/content/i18n/*.json` 中的 `eveTypePrice.*`。
- 悬停浮层会显示当前静态 API 结果，包括买卖均价、成交量和订单量。
- 如果某个字段当前没有已生成的数据，会在对应行显示当前 locale 下配置的“暂无报价”文案。

```mdx
可以直接写 <EveTypePrice typeId={28665} />。

如果你想指定市场区域，也可以写 <EveTypePrice typeId={28665} regionId={10000043} />。
```

## `EveFit` API

`EveFit` 是一个 `astro` 组件，右侧代码块直接复用 Starlight 的 `<Code>` 实现，因此外观会和 markdown 三反引号代码块保持一致。左侧槽位标题则通过 Starlight UI 翻译系统渲染，当前键位定义在 `src/content/i18n/*.json` 中的 `eveFit.section.*`。

| Prop     | Type                                                                                                                            | Default  | 说明                             |
| -------- | ------------------------------------------------------------------------------------------------------------------------------- | -------- | -------------------------------- |
| `name`   | `string`                                                                                                                        | Required | 配装名称。                       |
| `shipId` | `number`                                                                                                                        | Required | 舰船的 TQ `type_id`。            |
| `data`   | `Partial<Record<"high" \| "med" \| "low" \| "rig" \| "charges" \| "drones" \| "cargo", Array<{ id: number; count?: number }>>>` | Required | 按槽位或物品类别分组的配装条目。 |

行为说明：

- 左侧渲染列表会按 `high`、`med`、`low`、`rig`、`charges`、`drones`、`cargo` 的固定顺序分组显示。
- 左侧槽位标题通过 Starlight UI 翻译系统渲染，当前 locale 下会自动切换。
- 右侧代码块会生成可直接复制的纯文本 fit 文本，舰船和条目名称使用 `en`，但不会写出任何槽位标题。
- `shipId` 和各分组中的 `data.<section>[].id` 都会被纳入 `eveRefs.typeIds`，因此新增调用点后同样要刷新 inspect manifest。
- `high`、`med`、`low`、`rig` 分组中的 `count` 会展开成多行；`charges`、`drones`、`cargo` 分组中的 `count` 会折叠成 `xN`。
- `pnpm build:collect` 会在组件实际渲染时读取这些 prop 的求值结果；只要收集构建能正常运行，`shipId` 和 `data.<section>[].id` 就会进入 manifest。

```mdx
<EveFit
    name="新人挖坟"
    shipId={605}
    data={{
        high: [{ id: 11370 }, { id: 17938 }],
        med: [{ id: 5973 }, { id: 6131 }, { id: 22177 }, { id: 22175 }],
        low: [{ id: 1403, count: 2 }],
        rig: [{ id: 31213, count: 2 }],
        charges: [{ id: 30013, count: 16 }],
        drones: [{ id: 23707, count: 5 }],
    }}
/>
```

## Inspect 与生成

新增或修改这类组件引用后，推荐按如下顺序刷新数据：

先在 shell 或仓库根目录的 `.env` 中设置好 `EVE_DOCS_WORKSPACE`，然后运行：

```bash
pnpm generate:all
```

如果你想把最终站点渲染也串起来，可以直接运行：

```bash
pnpm build:all
```

数据生成步骤读取的是 TQ 源工作区，而不是预构建 bundle。对 `pnpm generate:all` /
`pnpm build:all` 来说，这个工作区需要提前通过环境变量提供：

- 在仓库根目录的 `.env` 中设置 `EVE_DOCS_WORKSPACE=/path/to/tq-source-workspace`
- 或在当前 shell 中预先导出 `EVE_DOCS_WORKSPACE`
- 如需临时覆盖单次命令参数，请直接运行 `pnpm generate:eve-docs-data -- --workspace /path/to/tq-source-workspace`
- 如需覆盖默认的工作区内缓存目录，可额外传入 `--resource-cache-dir` / `--workspace-cache-dir`，或设置 `EVE_DOCS_RESOURCE_CACHE_DIR`

该目录至少需要：

- `resfileindex.txt`
- `fsd/` 目录，或直接放置的 FSD 文件

如果存在 `start.ini`，生成器还会把游戏版本和 build 一并写进生成数据。

生成步骤会读取两份收集结果，只同步实际被文档调用到的资源：

- `src/generated/extension-ids.json`
  中的 `eveRefs.typeIds`
  包括 `EveType.typeId`、`EveTypePrice.typeId`，以及 `EveFit.shipId` / `EveFit.data.<section>[].id`
- `src/generated/extension-ids.json`
  中的 `eveRefs.locIds`
- `src/generated/extension-ids.json`
  中的 `eveRefs.iconIds`
- `src/generated/eve-type-prices.json`
  包括 `EveTypePrice.regionId` 和 `EveTypePrice.typeId` 的唯一组合，用于后续拉取市场价格快照

并写出：

- `src/generated/eve-type-prices.json`
- `src/generated/eve/data.ts`
- `src/generated/eve/type-price-data.ts`
- `src/generated/eve/icons/*.png`
- `src/generated/eve/types/*.png`
